# Group Assignment - UI UX

## Rules of Contribution

Each team member must make *some* contribution to the GROUP repository for thee required UI / UX elements, as proved by their authorship in the commit history of the repository.  If a group member has no contributions, they will receive a 0 grade for this portion of the group assignment - all other team members will receive the score set in the feedback.

## Assignment Taskings

Your group has now been through the grinder on refining your app idea, defining a user flow, and creating a set of wireframes.

It is expected that each of these pieces may still need tuning based on feedback and your team’s own refinement. However, your team still needs to commit to a core game plan.

Your **main branch** of your **group repository** needs to contain the following elements:

**Business Requirements / MVP**

README with the following sections \- but this time make it look good / presentable [https://www.markdownguide.org/cheat-sheet/](https://www.markdownguide.org/cheat-sheet/) 

App Name:

Vision:

Mission:

Your core user:

How your app will address:

* Search, View all, Create, Edit, Dashboard / Homepage

For:

* What, When, Why, Where, How

**UI UX Design**

**User flow** (or flows) addressing how the user will interact with your application to do tasks (Search for, View all of, Create a new record of, Edit a, Dashboard and / or Homepage to view / track…)  

* Depending on the length of your README file, you may just embed the user flow image(s) in the README. If you are going to break up the document, link to the .md file your userflow is in.

**Add a set of wireframes** that shows concepts of how your app will lay out different functions. The wireframes should address the different views your user will go through to perform actions based on your userflow. 

* Depending on the length of your README file, you may just embed the wireframes in the README. If you are going to break up the document, link to the .md file your wireframes are in.

Commit to the **brand guide** for your application. 

* Depending on the length of your README file, you may just embed the brand guide in the README. If you are going to break up the document, link to the .md file your brand guide is in.

## Ongoing / Feedback Response

The teams will be reviewing your submission and creating feedback using **Issues** in your team repository. You must respond to this feedback within **one week** by asking for clarifications, making adjustments, or defending a decision.

## Submission / Checkpoint

Submit the URL to your team's repo to the Dropbox in Pilot. Only one team member needs to submit.
